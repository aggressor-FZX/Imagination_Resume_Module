## Diagnosis

The demonstrated difference between this run and the withholding run is the
bridge set. In `dd68fc90` every bridge was **accepted**, so `_introduces_beyond`
never saw bridge wording as introduced content. The withholding shape is a
narrowed or removed bridge: `_apply_bridge_decisions` then rewrites the draft
with new wording and sets `requires_review`, which forces another review — and
that is exactly the `repair, review, repair, review` tail `b48e9c13` shows.

A code reading found a candidate: `_ACTIVE_BRIDGES` is set once at entry from
`permitted_bridges`, while `permitted_bridges` is reassigned to the narrowed
records later. If that is the defect, the exemption in `_introduces_beyond` would
still match the PRE-narrowing label and miss the replacement.

**This was NOT shipped.** No retained capture contains a narrow or remove
decision — all 24 recorded `accept` or no decision at all — so the candidate
could not be demonstrated, only argued. A speculative change here would alter
what the checker treats as introduced content with no evidence it fixes the real
failure, so it was reverted before commit.

One attempted repair WAS written and then reverted on the same principle: adding
the item's own source document to the evidence scope. It was tested against
retained capture `12ecfaa4` and did not change that outcome (the disputed item
already came from the document it cited), so it had no demonstrated effect.
